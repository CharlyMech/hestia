# Issues

Use GitHub issues to track bugs, feature requests, release tasks, and beta
feedback. Use the templates in `.github/ISSUE_TEMPLATE/`.

## Bug Reports

Open a bug report when the app behaves incorrectly. Include:

- App version from Settings.
- Build number from Settings.
- Device and iOS version.
- Flavor and backend environment.
- Steps to reproduce.
- Expected and actual behavior.
- Screenshots, screen recordings, or logs when useful.

Use a `fix:` title when the issue maps directly to a bug fix.

## Feature Requests

Open a feature request for user-facing behavior, integrations, or workflow
improvements. Include:

- Problem being solved.
- Proposed behavior.
- Alternatives considered.
- Any required backend, privacy, or release implications.

Use a `feat:` title when the work should result in a feature commit.

## Release And Docs Tasks

Use `docs:` for documentation-only changes and `chore:` for release, signing,
CI, dependency, or infrastructure work. In this project, `chore:` triggers a
major version bump on the next `main` release.

## Security

Do not file public issues for vulnerabilities. Use [SECURITY.md](SECURITY.md).
